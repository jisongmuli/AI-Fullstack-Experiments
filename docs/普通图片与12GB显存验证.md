# 普通图片输入与 12 GB 显存验证

本说明是实验一至五之后的补充测试，不改写原实验报告中的历史成绩。单模型尺寸和显存测试日期：2026-09-27；双模型交叉检查补充于 2026-09-28；小图与九宫格补充于 2026-10-11。测试机器为 NVIDIA GeForce RTX 5070 Ti Laptop GPU，早期 `nvidia-smi` 报告总显存 12,227 MiB、驱动 616.64。早期实验使用 PyTorch `2.13.0+cu130`，2026-10-11 运行环境为 `2.14.0+cu132`；复现时须记录实际 CUDA/PyTorch 版本。

## 结论边界

图片输入支持 JPG/PNG、单文件不超过 25 MiB、像素总数不超过 2,500 万。实测 100×100、200×200、400×400、800×600、1200×800、1200×675、1242×1660、1080×1080、1080×1350、1080×1440、1280×1280、1920×1080、2560×1440、3024×1964 和 3840×2160 均能完成解码与候选模型推理。模型内部统一处理为 224×224，原始 4K 细节不会完整保留。新版 API 对短边 200–511 像素的非 CIFAKE 图片也输出**实验性候选分数**；短边低于 200 像素弃判。32×32 CIFAKE 图片继续使用原教学模型。小图稳定性和九宫格解释见 [补充说明](2026-10-11_小图候选分数与局部敏感度.md)。

**能处理图片不等于能可靠判定真伪。** 普通图片由 Ateeqq SigLIP 和 NYUAD ViT 两个候选模型交叉检查：分别返回原始分数，再计算算术平均和分歧；页面还能叠加九宫格模糊遮挡敏感度。遮挡颜色仅说明哪格影响了模型高分，不是真实 AI 区域。若文件含已知生成参数字段或软件字段，最多显示字段名及软件名，不返回提示词或私人 EXIF。元数据可修改，模型一致也不证明来源。普通图片接口的来源决策保持未校准。任何分数均不是 AI 来源概率或“AI 创作比例”，不能用于自动处罚、判定作者或发布正式平台上线指标。要改为正式审核判定，须先取得目标平台的真实图和生成图盲测集，验证误报率、漏报率、不同分辨率/压缩率/生成器的性能及人工复核流程。

## 显存和速度

使用 `code/models/benchmark_image_sizes.py` 在 CUDA 上以同一张 512×512 来源图片缩放生成各尺寸 JPEG，记录从解码到单张**Ateeqq 模型**推理的耗时。结果见 `results/highres/image_size_benchmark.json`。这个方法只验证单模型输入和资源占用；放大后的图不是原生 4K 样本，不可用于 4K 准确率结论，也不能代表双模型接口的延迟。

| 输入尺寸 | 单张解码加推理 |
| --- | ---: |
| 100×100 | 8.5 ms |
| 800×600 | 14.8 ms |
| 1920×1080 | 27.4 ms |
| 2560×1440 | 42.9 ms |
| 3840×2160 | 96.9 ms |

PyTorch 记录的单模型峰值已分配显存为 393.8 MiB、峰值保留显存为 440.0 MiB；这些数字不包含 CUDA 上下文和桌面程序占用。相同来源图片在 100×100、200×200、400×400 时的候选分数分别约为 0.003、0.995、0.721，说明低分辨率输入非常不稳定。

双模型复测使用 `python code/models/benchmark_crosscheck.py`，结果保存于 `results/highres/crosscheck_size_benchmark.json`。同一张 512×512 来源图片缩放到指定尺寸后，每种尺寸先预热 1 次，再记录 2 次解码加推理：512×512 为 20.77/21.45 ms，1080×1440 为 43.32/45.29 ms，3840×2160 为 168.73/164.03 ms。双模型加载耗时约 532 ms，PyTorch 峰值已分配/保留显存为 722.3/800.0 MiB；`torch.cuda.mem_get_info()` 在加载前后分别报告约 11,042/10,278 MiB 空闲显存。当前 12 GB GPU 能运行单请求双模型推理。这些数字不包含浏览器和其他进程的完整占用，不代表并发容量、冷启动总耗时或 4K 识别准确率。

## 跨来源结果

三个 Apache-2.0 候选模型都缩放到 224×224 输入。数值来自 `results/highres/evaluation.json`，鞋图/艺术图每类抽样 200–400 张，512 主题图每类 200 张。下表是固定 0.8 AI 判定阈值下的真实图误报率与生成图漏报率，样本量有限，且同一批外测集已用于比较候选，不能再当最终独立验收集。

| 模型 | 鞋图误报/漏报 | 艺术图误报/漏报 | 512 主题图误报/漏报 |
| --- | ---: | ---: | ---: |
| Ateeqq SigLIP | 59.5% / 9.3% | 70.0% / 15.5% | 33.5% / 6.5% |
| prithivMLmods SigLIP2 | 99.5% / 1.0% | 59.5% / 77.5% | 100.0% / 0.0% |
| NYUAD ViT | 3.5% / 38.5% | 12.0% / 83.5% | 26.5% / 19.0% |

这些结果表明候选模型严重依赖图像来源；模型卡自报的同源准确率不能替代真实平台验证。`results/highres/CANDIDATE_EVALUATION.md` 另记录了 SwinV2 候选在鞋图和艺术图上的相反表现。中文文本检测另见 `data/text_chinese/README.md`；其同源成绩不能作为小说或真实平台内容的上线指标。

交叉检查使用上述同一批样本，将 Ateeqq SigLIP 与 NYUAD ViT 分数取固定算术平均。`results/highres/crosscheck_evaluation.json` 同时保存逐样本预测 CSV 的 SHA-256。下表中的误报和漏报采用 **0.2/0.8 离线审计阈值**，分母分别是全部真实图和全部生成图，介于阈值之间的样本计入弃判；线上普通图接口依然一律弃判。

| 公开集 | 样本数 | AUC | 离线覆盖率 | 真实图误报率 | 生成图漏报率 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 鞋图 | 800 | 0.890 | 46.9% | 2.0% | 5.8% |
| 艺术图 | 800 | 0.540 | 33.0% | 13.5% | 14.3% |
| 512 主题图 | 400 | 0.917 | 63.3% | 8.0% | 4.0% |

艺术图 AUC 接近随机，按全部真实图计算仍有 13.5% 被离线阈值错判为 AI；按已覆盖的真实艺术图计算，误报率为 35.8%。公开集曾参与模型选择，因此这些数字是**探索性比较，不是独立验收，更不能外推为真实平台准确率**。双模型平均值改善了部分公开集的离线误报，但没有解决跨来源失准。

## 复核命令

在项目根目录、已安装对应依赖的 Python 环境中运行：

```powershell
python code/models/download_highres.py
python code/models/evaluate_highres.py --model ateeqq --dataset shoes --dataset art --dataset rhythmghai512 --per-class 200
python code/models/benchmark_image_sizes.py --model ateeqq
python code/models/evaluate_crosscheck.py
python -m unittest discover -s code/server/tests -v
python -m uvicorn app:app --app-dir code/server --host 127.0.0.1 --port 8002
```

在这台 Windows/Python 3.12 机器上，可建立项目专用的 CUDA 环境：

```powershell
py -3.12 -m venv .venv-cuda
.\.venv-cuda\Scripts\python.exe -m pip install --index-url https://download.pytorch.org/whl/cu130 torch==2.13.0+cu130 torchvision==0.28.0+cu130
.\.venv-cuda\Scripts\python.exe -m pip install -r code/server/requirements.txt
.\.venv-cuda\Scripts\python.exe -c "import torch; print(torch.cuda.is_available())"
.\.venv-cuda\Scripts\python.exe -m uvicorn app:app --app-dir code/server --host 127.0.0.1 --port 8002
```

第 4 行须输出 `True`；CUDA wheel 下载约 1.9 GB，属于运行环境，不计入数据集容量。网页地址为 <http://127.0.0.1:8002/>。若端口已被占用，使用其他端口。当前图像/文本分数均只供人工筛查参考。
