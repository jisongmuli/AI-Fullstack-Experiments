# 小图候选分数与局部敏感度说明（2026-10-11）

用户示例为 289×202 像素，旧版因短边不足 512 像素直接弃判。新版对短边 **200–511 像素** 的 JPG/PNG 运行现有 SigLIP、ViT 双模型，返回两个分数、算术均分及模型分歧。页面把均分称为**实验性模型风险指数**，不是图中 AI 内容所占比例，也不是经目标平台校准的概率。短边低于 200 像素的图仍不输出分数；32×32 CIFAKE 教学样本保留原独立路径。普通图的 API `decision` 仍为 `uncertain`，避免把筛查信号作为已证实的来源鉴定。

新版还对九宫格逐格做高斯模糊遮挡，比较遮挡前后两模型均分的变化。正向下降越大，表示该格对**当前模型的高风险输出**越有影响；负向变化保存在 `raw_deltas` 中供审计，但不会染成“高风险区域”。页面叠在原图上的颜色是相对敏感度，不是局部 AI 生成概率、生成像素比例或篡改真值；所有变化都很小时保持空白并说明“未发现明显的正向敏感区”。图像遮挡作为模型解释方法有[早期研究基础](https://cs.nyu.edu/~fergus/papers/zeilerECCV2014.pdf)，但[显著图可靠性研究](https://papers.neurips.cc/paper_files/paper/2018/hash/294a8ed24b1ad22ec2e7efea049b8737-Abstract.html)说明视觉上看似合理的热图不能自行证明解释正确。本项目尚无已标注的局部 AI 编辑真值，因而不能声称定位准确率。

## 低分辨率稳定性探索

`results/highres/lowres_paired_stability.json` 使用此前已看过的 100 张 CommunityForensics-Eval 规范化 JPEG（50 张 Firefly Image2、50 张 LAION）再次降采样和编码。这是**后验敏感性测试**，不是独立低分辨率准确率验证；289×202 变体还对原正方形进行了几何拉伸，与原生风景照片不同。

| 变体 | 与 512×512 基线相比的共识分类改变 | 均分绝对差第 90 百分位 |
| --- | ---: | ---: |
| 289×202 JPEG | 8/100 | 0.111 |
| 202×202 JPEG | 14/100 | 0.453 |
| 160×160 JPEG | 19/100 | 0.473 |
| 128×128 JPEG | 28/100 | 0.496 |

因此 200 像素只是给出实验性候选分数的工程下限，不是经过独立数据校准的可靠判别门槛。原数据集的许可为 CC BY-NC-SA 4.0，仅限非商用研究/教学；不能把这批图片作为商业平台的训练或上线验收数据。[官方数据卡](https://huggingface.co/datasets/OwensLab/CommunityForensics-Eval)

## 性能与复算

`results/highres/local_evidence_resource_benchmark.json` 记录本机 RTX 5070 Ti Laptop（约 12 GB 显存）单图暖机后三次计时中位数：289×202 仅双模型约 17.5 ms，连九宫格约 127.7 ms；512×512 为 19.9/172.7 ms；4K 为 167.6/370.3 ms。九宫格峰值 **PyTorch CUDA 分配量**约 742 MiB，这不是整机显存占用，也不是并发容量证明。启用热图与不启用热图的整图分数在基准样本上完全一致。

复核命令：

```powershell
python -m unittest discover -s code/models/tests -q
python -m unittest discover -s code/server/tests -q
python code/models/evaluate_communityforensics.py --offline-recompute
```

在图片页或 Agent 页上传图片即可看到自动生成的候选分数及可用时的局部敏感度。结果不需要用户手工计算；若要用于处罚、下架或作者身份判断，仍必须先完成目标平台的独立盲测和人工处置流程。
