# 文档 AI 检测与下划线报告使用说明

本轮增加了文档上传、长文分段检测、原文下划线标注、评分覆盖率、报告导出与 Agent 文档工作流。检测自动运行，无须先人工确认才能查看结果。当前模型仍是实验性筛查模型；新增文件格式和标注功能不等于已经证明检测准确率提高。

## 怎样使用

1. 双击项目根目录的 `启动系统.cmd`，进入 `http://127.0.0.1:8002/`。
2. 在左侧选择“文档检测”。上传文件，或切换到粘贴长文，点击“检测文档并标注”。
3. 查看 AI 特征覆盖率、可评分覆盖率及片段分数分布。在原文区域打开下划线标注，可显示未评分内容的虚线提示。选择片段或来源位置可定位到对应提取文本。
4. 下载 Word、HTML 或 JSON 报告。HTML 报告可在浏览器中打开，再用“打印 → 另存为 PDF”；这不是直接在原 PDF 上添加标注。
5. 点击“交给 Agent 汇总”，可以复用已经完成的文档结果，无须重新计算。Agent 的“文档”附件也可以直接上传文件，并与图片一起提交；粘贴文本与文档附件应分别提交。

## 支持的文件与范围

| 输入 | 范围 | 提取方式与限制 |
| --- | --- | --- |
| DOCX | 最大 20 MiB | 按正文顺序读取段落及表格；不执行宏或外部链接。原分页、图片、页眉页脚、脚注、批注和复杂公式不还原 |
| PDF | 最大 20 MiB、200 页 | 读取已有文本层及页面位置；不执行 OCR。扫描件、加密或损坏文件会提示转换后重试。分栏和复杂表格可能改变阅读顺序 |
| TXT / MD | 最大 20 MiB | 支持 UTF-8、带 BOM 的 UTF-16、GB18030；编码异常或二进制内容不会得到伪造的 0% 结果 |
| 粘贴文本 | 最多 100,000 字符 | 换行统一为 LF。字符计数和位置按 Unicode 字符计算，emoji 不会把后续下划线位置移错 |

所有文档提取后的文本最多 100,000 字符、2,000 个评分片段。超限会明确拒绝，不会截断后宣称整篇检测完毕。旧版 `.doc` 请先在 Word 中另存为 `.docx`。文本检测页和 Agent 直接粘贴的上限仍为 10,000 字符；更长内容请通过文档上传。

## 百分比怎样理解

页面主要输出的是可复算的覆盖率，不能把它解释成真实 AI 撰写比例。

| 指标 | 计算 | 含义 |
| --- | --- | --- |
| AI 特征覆盖率 | 高风险片段的非空白字符数 ÷ 全文非空白字符数 | 全文中有多少字符处在被模型标注的片段内 |
| 可评分覆盖率 | 已评分片段的非空白字符数 ÷ 全文非空白字符数 | 模型实际上评分了多少内容 |
| 已评分内容中的高风险占比 | 高风险片段的非空白字符数 ÷ 已评分片段的非空白字符数 | 与全文覆盖率的分母不同，不能混用 |
| 可评分片段模型均分 | 按非空白字符数加权的片段模型分数均值 | 描述性统计，不是整篇 AI 来源概率 |
| 整篇模型风险分数 | 现有模型在适用输入上的输出 | 超出范围、评分覆盖不足或片段明显冲突时不提供 |

例如，全文 1,000 个非空白字符，只有 600 个可评分，其中 300 个在高风险片段内：AI 特征覆盖率为 30%，可评分覆盖率为 60%，已评分内容高风险占比为 50%。未评分的 400 个字符不会被记为人类创作。完全没有可评分内容时，覆盖率显示缺失或“未评分”，不会把 AI 特征覆盖率显示成确定的 0%。

下划线沿用现有片段模型的高风险阈值 0.99，整段达到阈值才标注。阈值不是“99% 确定由 AI 写成”。没有下划线也不证明人类创作。当前没有经过独立验证的逐字、逐句混合作者真值，因此不把整段评分包装成逐字来源定位。明显的写作指令、明确标记的引用和代码围栏等可被排除；普通 Word 引用、参考文献和表格不能保证全部自动识别。

## 相比原版增加的能力

- 统一处理四种文档格式，长文无需手工拆分。
- 在提取原文中直接显示下划线，保留未评分内容，支持定位和开关。
- 同时展示全文覆盖率和可评分覆盖率，减少不同分母带来的误解。
- PDF 保留页码来源，Word 提供正文或表格位置。
- 用分数分布展示段落差异；冲突文本不生成虚假的统一来源概率。
- 报告记录文件指纹、模型版本、时间、片段位置及依据，便于复算与追踪。
- Agent 接收图片和文档，分别汇总结果；已完成报告可直接交给 Agent，不重跑模型。
- 模型指纹按服务实例缓存，长文不再逐段重复读取大型图像模型文件。

图像九宫格敏感度、双模型分歧与 C2PA 内容凭证保留原有独立含义。它们与文档分数不会混成一个综合“AI 率”。

## 数据留存与导出

上传原文件不在服务端保存到磁盘。提取文本及结果仅在当前本地服务内存缓存，最多 30 分钟、20 份、32 MiB；达到数量或内存上限会提前移除旧报告，重启即失效。后台到期清理不依赖用户再次请求。可以删除当前报告，删除后下载链接失效。

浏览器检测历史默认关闭。主动勾选后只保存文件名、时间、百分比及报告标识等摘要，最多 20 条；不保存原文。清空浏览器历史删除的是这些摘要，不等于删除所有服务端报告。下载到电脑的 Word、HTML、JSON 文件由用户自行管理，不随缓存过期而消失。

上传文件指纹是原文件字节的 SHA-256；粘贴内容指纹是换行规范化后 UTF-8 文本的 SHA-256。报告的 `source_sha256_kind` 区分两种情况。导出的 Word 和 HTML 都是“提取文本的标注报告”，不是保持原文件版式的批注副本。

## 市面产品参考

本轮参考的是可核对的产品流程，未复制其模型、商业评分或准确率声明。

- [GPTZero 官方使用说明](https://support.gptzero.me/articles/9172706201-how-do-i-use-gptzero)：文件上传、整体结果与文本高亮。
- [Turnitin 官方 AI Writing Report 说明](https://guides.turnitin.com/hc/en-us/articles/22774058814093-Using-the-AI-Writing-Report)：区分合格文本及检测比例，并解释非散文内容与误报问题。
- [Copyleaks 官方文档检测 API 说明](https://docs.copyleaks.com/guides/authenticity/detect-ai-generated-content/)：文档提交、提取文本、结果与报告导出。

本项目采用现有中文、英文段落模型，没有获得这些商业产品的检测能力，也没有复现其准确率。详细的真实平台验收缺口仍见项目根目录 `上线验收清单.md`。

## 复现与验收

运行 `python -m unittest discover -s code/server/tests -v` 验证提取、异常输入、偏移、百分比分母、导出和缓存。浏览器需验证实际上传、文件下载内容及移动端布局，不能只看接口返回成功。

`scripts/verify_document_workflow.py` 使用本地公开中文测试数据与真实 API 生成 DOCX、PDF、TXT 输入、带标注报告及约 10 万字符测试。其样本按分数范围选取，仅用于展示和格式流程检查，不能用来计算检测准确率。结果位于 `results/document_qa/real-workflow-checks.json`，浏览器测试记录位于同目录下的 `ui-live-checks.json`。

代码分工：`documents.py` 负责提取与逐段统计，`document_reports.py` 负责导出，`report_store.py` 负责限额和到期清理，`app.py` 连接 API 和 Agent，`web/document.js` 负责原文标注与文档交互。文档功能测试不等于分类效果验收；上线仍需真实平台独立盲测、混合文本逐段真值和预先冻结的误报、漏报及覆盖率门槛。

PDF 的文本块与排序方法采用 [PyMuPDF 官方文本提取接口](https://pymupdf.readthedocs.io/en/latest/app1.html)，额外按行间距和列位置组合段落；复杂布局无法保证自动恢复。依赖已写入服务的 `requirements.txt`，正式发布前仍需核对新增依赖及既有数据、模型的许可。此环境未提供 LibreOffice，Word 导出报告的版面使用本地 Office 兼容程序生成 PDF 后逐页检查；示例 4 页的下划线、页码、中文及 emoji 显示正常，QA 文件保存在 `results/document_qa/`，不是平台分类准确率证据。
