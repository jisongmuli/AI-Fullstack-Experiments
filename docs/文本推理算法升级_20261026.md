# 文本推理算法升级

## 已实现

文本算法继续使用已训练的字符 TF-IDF、逻辑回归和既有校准参数，本轮升级推理执行方式与有效特征检查。

1. 增加 `predict_text_batch`：按中英文分组，每批默认处理 32 条输入，稀疏特征矩阵直接进入分类器。
2. 同一次调用中的重复文本只计算一次，单段原文与整篇相同时共用结果。返回值与证据列表分别复制。
3. 英文特征名称在模型载入时读取一次，避免每个段落重新遍历 10,000 项词表。
4. 有效特征数为零时，输出 `insufficient_model_features`，分数为空，提示补充完整正文。这些段落也从可评分覆盖率中排除。
5. 原始字符位置、中英文路由、中文 NFKC 规范化、校准参数、混合段落处理和高亮阈值沿用已有规则。

重复文本的复用仅发生在当前调用内部；调用结束后释放文本映射。模型实例保存权重与特征名称。

## 修复的判断问题

旧版对于 `qzxvjk` 重复字符串和未登录汉字 `龘` 重复文本，特征矩阵为空，仍将分类器截距送入校准器，分别给出 0.020736 和 0.022298 的分数，判断为 `human`。新版对两者明确提示有效特征不足，分段与文档统计保持一致。

## 本机测量

比较基线为本仓库提交 `ef605bc`，双方使用相同的已训练权重、CPU 和生成测试输入。模型载入后预热，分别运行 7 次，记录中位数。以下两组段落内容互不重复：

| 输入 | 旧版推理 | 新版推理 | 提速 |
| --- | ---: | ---: | ---: |
| 40 段英文 | 104.675 ms | 8.501 ms | 12.31 倍 |
| 60 段中文 | 20.470 ms | 9.826 ms | 2.08 倍 |

另有包含重复段落的对照，明细与输入生成方式保存在 `scripts/benchmark_text_inference.py` 和 `results/algorithm_20261026/text-benchmark.json`。测量范围为文本推理，文件解析、报告生成和网络传输分别由完整流程检查覆盖。

## 验证

- 21 组正常文档样例、128 条批量输入与旧版逐项比较，分数、判断、分段位置和证据一致。
- 新增 11 项批量推理、语言路由、容量边界、复用隔离、无效特征、覆盖率和原文位置检查。
- 服务端 107 项、模型单元 23 项、实际模型分段 12 项、中文模型 3 项，共运行 145 项测试：144 项通过，缺少官方 C2PA 样本的 1 项跳过。
- 新版 HTTP 实际模型检查 6 项通过，包含 18,198 字符、200 段的后台任务和 JSON 报告原文位置核验。
- 完整实际模型流程通过：中英文文本、教学图片与普通图片双模型、DOCX/PDF/TXT、三种导出、Agent、LoRA 预览；后台任务专项检查通过。
- 本轮样例用于功能、结果一致性与速度核验；识别准确率评测留给后续独立标注集。

## 本机访问

新版实例运行于 `http://127.0.0.1:8003/`。原 8002 实例继续运行此前载入的算法代码。自动审批策略拦截了停止并重启 8002 的操作，因此此次用独立端口完成验证。之后重新启动默认服务时，会载入磁盘上的新版代码。

## 继续提升识别效果的方向

优先补充独立标注的中英文真实成稿与新生成器样本，按来源及生成器分组，再分别进行训练、参数选择、概率校准和最终测试。模型比较记录误报率、漏报率、覆盖率和校准曲线。新候选模型通过这些比较后，再更新正式权重。

图像方向可进一步比较原图、压缩图与不同裁剪方式下的双模型输出，使用单独验证集选择融合方式。当前本机保留已有图像推理链路。

批量推理与特征提取优化参照 [scikit-learn 计算性能说明](https://scikit-learn.org/stable/computing/computational_performance.html)；训练与评测划分参照 [数据泄漏说明](https://scikit-learn.org/stable/common_pitfalls.html#data-leakage)，校准比较参照 [概率校准文档](https://scikit-learn.org/stable/modules/calibration.html)。
