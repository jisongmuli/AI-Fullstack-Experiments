# 一 这次实验到底做什么

实验一的核心不是训练一个“万能 AI 检测器”，而是把公开数据变成可信、可复现、可检查的数据集。项目题目是《多模态AIGC内容检测与可信编辑系统》。本次只处理图像检测与英文文本检测所需的数据；编辑功能和用户界面属于后续实验。图像、文本没有一一对应关系，所以“多模态”表示系统未来会处理两种内容，不表示我们已有图文配对样本。

这份说明面向六位组员和报告答辩。做完应能回答：原始数据从哪里来、是否真的下载了、原始数据有什么问题、怎样清洗和划分、增强到底有没有帮助、为什么较高的同源分数不等于真实世界有效。

# 二 文件和运行顺序

项目根目录是 `AIGC实验1`。所有脚本从该目录读取或写入数据。`code/` 是代码，`data/raw/` 是不修改的源 ZIP 与来源说明，`data/images/` 和 `data/text/` 是处理结果，`results/` 是审计指标、训练结果和图表。完整目录树和每列字段见 README。

推荐用 Python 3.12 建立独立环境，安装 README 所列依赖，按以下顺序执行。第一次运行需能访问 Kaggle 公开接口；本机已经有原包时，下载脚本仍会读取元数据并复核 ZIP。准备脚本会重建派生文件，所以不要手工修改派生 CSV 后期望重跑仍保留修改。

```powershell
cd AIGC实验1
python code/download_sources.py
python code/prepare_dataset.py
python code/evaluate_augmentation.py
python code/audit_confounds.py
python code/audit_privacy.py
```

五个脚本的结果依次为：原包和 SHA-256；图像、文本、元数据及质量 JSON；图像和文本增强对照指标；长度捷径诊断与目录图；隐私模式命中统计。机器配置会影响耗时，准确率也可能因 PyTorch 版本和 CPU 算子差异有微小浮动；本报告数字对应随附 JSON 文件。

# 三 第一阶段 多源数据获取

## 3.1 为什么选这三种数据

CIFAKE 是 12 万张 32×32 图片，真实类来自 CIFAR-10，生成类据发布者说明来自 Stable Diffusion 1.4；它适合演示图像采集、去重与小型模型比较，但不代表各种分辨率与生成器。主文本集 6069 条用于训练和同源划分；另一个文本集 2750 条只做外部检验，不混进训练。结构化表格不是另找一个无关数据集，而是给每张抽样图像计算元数据，形成与项目相关的 CSV。这三类满足任务书的结构化、文本、图像要求，但结构化表与图像不是独立证据源。

## 3.2 怎样确认真的获得了数据

`download_sources.py` 请求 Kaggle 数据集元数据接口和 ZIP 下载接口，校验 ZIP 每个成员能读取，计算压缩包 SHA-256。三份本地原包分别为约 109.6 MB、2.49 MB 和 1.47 MB；精确字节数与哈希在 `data/raw/*_source.json`。脚本记录下载时间与页面说明。报告引用原始页面而非上传本地数据，避免把未经核验的文本版权内容再分发。

要注意网页介绍可能与文件不一致：主文本页面声称有 `source` 列，实际 CSV 只有 `Unnamed: 0, Text, Author`；外部文本页面把总数写为“N”，实际下载的 CSV 为 2750 行。因此任何字段和行数必须以当前下载文件检查为准。平台许可字段也不是每条文章的权利证明。

# 四 第二阶段 清洗和增强

## 4.1 图像审计

`prepare_dataset.py` 对 120000 个 ZIP 成员逐个用 Pillow 解码、转为 RGB、读取尺寸，计算源文件哈希与 RGB 像素哈希。文件哈希相同说明压缩文件字节相同；像素哈希相同说明解码后的 RGB 像素相同，后者更适合排查相同画面。本次 1336 条为多余的像素重复记录，解码失败 0，非 32×32 尺寸 0。记录中的 `duplicate_of` 指向更早出现的同像素图片，便于复查；“重复”不是说作者故意抄袭，只是不能让相同像素跨训练和测试。

图像从原作者的 train 池抽 4000 张训练和 800 张验证，从原 test 池抽 800 张测试。分类标签 0=REAL、1=FAKE，每组两类各占一半。所有选中图像另存为 32×32 RGB PNG；转换格式不增加像素信息，放大到 224×224 也不会变清晰。源清单、抽样清单及导出图像留存；处理后 5600 张的像素哈希交叉为 0。

## 4.2 图像结构化表

每张抽样图像衍生 `brightness`（RGB 均值）、`contrast`（RGB 标准差）、`file_bytes`（原文件大小），再构造 `bytes_per_pixel=file_bytes/(32×32)`。这是任务书的结构化数据与特征组合练习。文件大小受 JPEG 压缩率、编码器和内容纹理共同影响，不能说文件大就更可能是 AI。标签和图片路径只是管理字段，不能错误地把类别字符串放进输入特征。

Min-Max 归一化公式为 `z=(x-训练集最小值)/(训练集最大值-训练集最小值)`；参数只在训练集计算，验证/测试只能 transform。代码使用 `clip=True` 把超出训练范围的值限制到 [0,1]。如果先对全量数据计算最大最小值，就把测试集信息提前泄漏给训练流程。实际参数在 `results/image_scaler_parameters.json`。

## 4.3 文本清洗与最重要的质量发现

文本先解码 HTML 实体、去标签、统一 Unicode 为 NFKC、合并连续空白；再映射标签并按规范化文本哈希去重。主集原始 6069 行，没有空白文本、非法标签或精确重复。这说明清洗不一定会减少行数。外部集 2750 行有 330 个多余精确重复，最终 2420 行。

主集人类文章字符中位数 1871，AI 样本中位数 332。若不处理，模型只要依据长度就能几乎猜中类别。`audit_confounds.py` 用字符数的 `log1p` 作为唯一特征训练逻辑回归，原始测试准确率 99.84%。这不是 AI 写作风格的识别成果，而是数据采样规则留下的捷径。为削弱它，对每条人类原文抽取一个连续片段，目标词数从 AI 样本词数分布随机抽取，保留原始全文清单和片段起始词位置。处理后两类词数中位数同为 47、字符中位数 330/332；长度单特征测试降到 50.74%。外部集也做同样处理，但其两类字符中位数仍为 79/95，且题材来源依然不同。匹配长度不能证明标签绝对正确或其他偏差不存在。

## 4.4 什么时候划分，什么时候增强

主文本去重、长度处理后才以种子 42 按标签分层划分 8:1:1，即训练 4855、验证 607、测试 607。分层使每组类别比例相近。图像保留源作者的测试池，只从源训练池划验证集。增强永远仅发生在训练阶段；如果先增强全量再划分，一条原文和它的同义词版本可能落在训练与测试两侧，评估会变虚高。

图像增强只做随机水平翻转、±8° 旋转；文本在约 25% 训练样本中每条替换一个常见同义词，产生 599 条派生训练记录。文本平均句级 BLEU 为 0.9405，说明字面变化较小，但 BLEU 不是事实与语义保留的充分证明。涉及否定、术语、数字或引用时，仍需人工检查。

# 五 第三阶段 数据集建设与评价

标准格式为 PNG、JSONL、CSV。图像清单记录原路径、类别、尺寸、格式、像素/文件哈希和目标路径；文本 JSONL 的每行都是可独立解析的 `sample_id,text,label,source_dataset`；结构化元数据 CSV 使用小写下划线列名。每条派生增强文本有 `aug_` ID 和 `augmented_from`，可回查原文。`README.md` 说明用法、字段与下载，`DATA_CARD.md` 说明来源、标签、代表性、许可、隐私及禁用情形。

| 对照 | 验证准确率 | 同源测试准确率 | 外部测试准确率 |
| --- | ---: | ---: | ---: |
| 图像小 CNN，原始训练 | 81.75% | 81.25% | 无 |
| 图像小 CNN，训练增强 | 82.38% | 81.63% | 无 |
| 文本 TF-IDF+逻辑回归，原始训练 | 93.57% | 95.88% | 55.21% |
| 文本 TF-IDF+逻辑回归，训练增强 | 94.23% | 96.21% | 60.12% |

模型设置要固定，才能把两行之间的差异主要归于训练增强。图像准确率增幅很小，而且人类图像误报比例从 13.25% 增到 14.25%；文本同源看似很高，外部集却明显下降。外部集没有与主集完全一致的题材、来源和长度分布，所以成绩下降不能归因于一个单独因素。即使同源测试 96% 也不能用于判断某个学生是否使用了 AI。

任务书提到自动化策展工具。我们的脚本已经形成固定、可重复的流水线，但没有安装 Data-Juicer 或 NeMo Curator，也没有手工清洗的计时对照。本次准备脚本测得图像约 18.39 秒、文本约 1.18 秒，只能描述该设备上的一次运行。不要把不同运行之间的耗时差直接解释为算法速度提升。

# 六 答辩时如何解释关键问题

**为什么没有从网站爬文章？** 本项目直接下载公开数据集 ZIP，网页抓取不是取得文本的必要步骤。来源页面仍需核验许可、原作者和 AI 训练 opt-out 信息；因为逐条来源缺失，数据卡把这项列为未解决风险。

**为什么要保留原始文件？** 清洗可能误删合法样本，长度摘录也会改变写作上下文。源 ZIP 和原文清单使每一步都能回溯，可检验报告数字是否真实。

**为什么随机种子固定还不能证明增强有效？** 固定种子保证本次比较可复现，但只做了一次划分和一次训练，差距可能来自样本波动。后续要做多种子重复、置信区间与更真实的外部集。

**数据是否完全合规？** 只能确认公开访问和页面标注的许可字段。隐私启发式扫描对主/外部文本发现 99/2 条疑似电话格式、邮箱格式均 0，处理后 PNG 的 EXIF 为 0；数字命中可能是日期，姓名等内容不在规则覆盖内。主文本缺少逐条 `source`，尚未逐条核验版权和个人信息，因此不能声称“完全合规”或公开再分发全文。图像页许可正文与平台字段也需进一步核对。

**可信编辑为什么还没有？** 实验一的课程任务是数据采集、预处理和建设。编辑模块后续应检查重复、空泛、逻辑与原意保留，不能把“绕过 AI 检测器”当目标。检测界面必须允许“无法可靠判断”并交由人复核。
