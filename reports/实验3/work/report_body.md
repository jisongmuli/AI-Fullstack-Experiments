# 一 实验目的

本实验围绕多模态 AIGC 检测项目的既有模型开展算法优化，选择资源占用作为主要优化维度，同时考察图像推理导出带来的执行效率变化。实验对象为实验二得到的五层卷积图像分类器和字符级 TF-IDF 逻辑回归文本分类器。图像分支采用 TorchScript 保存可执行推理图，文本分支将特征词表由 30000 维压缩为 10000 维，并保留与原分类任务一致的输入、标签和输出接口。

实验三的重点是建立可核查的优化对照。我们从模型文件、可学习参数、数值数组、稀疏特征、推理延迟、批处理吞吐量和进程工作集等层面展开测量，并结合实验一的数据特点分析结果。现有模型在同一 CPU、相同线程数和相同输入条件下比较，质量指标与资源指标分别记录，便于解释每项变化产生的原因。

任务书要求从六项任务中至少选择一项优化任务。本实验选择任务 3.1.5 的资源占用优化方向，将实现方式适配到项目实际采用的稀疏文本模型；图像分支增加任务 3.1.4 所关注的推理效率比较。选做部署部分采用本机 CPU 完成推理验证，ONNX Runtime、TensorRT 和 OpenVINO 作为后续部署路径进行适配分析。[1]

本实验希望回答三个具体问题。第一，特征数缩减三分之二后，模型存储、数值数组和内存占用分别减少多少。第二，图像推理导出能否在保持输出一致的条件下降低延迟，收益在单张和批量输入之间如何变化。第三，模型计算量、文件大小和实际执行时间之间具有怎样的联系，如何为本地交互系统选择合适的部署版本。

报告采用项目原实验记录与本机复测相结合的方式。分类质量引用项目已保存的实验二与实验三技术记录，模型体积、结构、延迟、吞吐量、内存及导出一致性在 2026 年 10 月 25 日重新核验。复测只读取已有模型，保持业务程序和模型权重原样。主要结论是文本压缩显著降低了存储及加载内存增量，图像导出改善了单张推理效率，两种方法分别解决了部署中的不同成本问题。

# 三 实验内容与步骤

## 3.1 需求分析与优化方案

项目面向图像和文本两类输入。图像分支完成 32×32 RGB 教学数据分类，文本分支处理经过长度控制的英文片段。两种模型的计算结构差异较大：卷积网络的成本集中在二维特征图计算，字符模型的成本集中在字符串分解、词表查询和稀疏矩阵构建。针对这种差异，我们分别选择推理导出和特征裁剪，而不是为两个分支套用同一个压缩流程。

资源优化的主要目标是使文本模型文件至少缩小 40%，并将验证集宏平均 F1 的下降控制在 1 个百分点以内。内存方面按照任务书记录加载开销、推理峰值和连续 1000 次调用的变化；其中进程峰值下降 30%和波动不超过 5%作为比较指标。图像导出侧关注 P50、P95、吞吐量及输出一致性，使用任务书的延迟下降 40%和吞吐提升 50%作为参照目标。

在模型结构选择上，本项目沿用实验二已经训练完成的五层卷积网络与稀疏字符分类器。量化通常改变数值表示精度，结构剪枝改变可执行网络的宽度或连接，蒸馏通过教师模型指导学生训练。本次文本优化改变的是特征空间规模，核心操作包括控制词表容量、重新拟合对应的分类器以及按验证集质量选择部署版本。报告据此采用“特征裁剪与资源优化”的名称。

## 3.2 实验一数据与实验二模型的衔接

实验一对 CIFAKE 图像进行了格式检查、像素哈希去重及训练验证测试划分，选取 5600 张图像构成教学子集。实验二使用其中 4000 张训练、800 张验证、800 张测试。真实图像和 AI 图像统一映射为标签 0 和 1，输入为三通道 32×32 像素。图像训练阶段采用水平翻转和小角度旋转，验证与测试保持确定性读取。

英文主文本集清洗后保留 6069 条记录。为控制原始人类文本较长的问题，实验一将人类文本整理为连续片段，使两类文本的字符长度中位数接近：人类片段为 330，AI 文本为 332，词数中位数均为 47。主集按分层方式划为训练 4855 条、验证 607 条、测试 607 条；训练时另加入 599 条同义词增强文本，训练输入总数为 5454 条。

这些数据特点直接影响优化方案。图像空间尺寸固定，便于分析每层输出形状与卷积运算量，也适合建立相同输入下的导出一致性对照。文本片段较短，字符 n-gram 数量受到句长约束，即使全局词表较大，单条输入仍只激活其中少量特征。因此，词表压缩的存储收益与单条推理收益需要分别测量。

## 3.3 图像模型结构核查

图像模型 ImageCNN 由五个 3×3 卷积层、三个批归一化层、两次最大池化、全局平均池化和一个二分类线性层组成。前两层输出 32 个通道，中间两层输出 64 个通道，最后一个卷积层输出 128 个通道。池化将空间尺寸依次从 32×32 降到 16×16 和 8×8，最后将每个通道汇总为一个数值。

原实验采用 AdamW，初始学习率 0.001，权重衰减 0.0001，每 4 轮将学习率减半，共训练 8 轮。模型按验证集宏平均 F1 保存最佳状态，权重文件记录的最佳轮次为第 6 轮。本次重新读取检查点，确认其架构名称、随机种子和最佳轮次字段与原实验说明一致。

## 3.4 文本模型表示与特征裁剪

文本模型采用 char_wb 分析器提取长度为 3 到 5 的字符片段，在词边界内构建特征，并设置 min_df 为 2、sublinear_tf 为真、向量归一化方式为 L2。字符特征能够表示词形、常见短语片段和标点周边模式，适合处理已经过长度匹配的短英文片段。[3]

TF-IDF 的构造先计算字符片段在单条文本中的出现次数，再结合训练语料的逆文档频率缩放。平滑 IDF 使用文档总数和包含该特征的文档数计算，随后将输入表示为稀疏行向量。词表与 IDF 均从训练数据拟合，验证和测试阶段使用固定映射。

@EQ idf

分类器为带类别平衡权重的逻辑回归，正则化参数 C 为 1，最大迭代次数为 1000，随机种子为 42。分类器对稀疏向量计算线性分数，再进行类别决策。二分类情况下，可学习参数包括 d 个系数和 1 个截距，因此完整模型有 30001 个分类器参数，压缩模型有 10001 个。[4]

@EQ linear

词表裁剪保留相同的特征提取规则，把 max_features 从 30000 调整为 10000。原脚本针对不同容量分别拟合特征变换器与分类器，通过验证集宏平均 F1 检查候选版本。由于压缩版本经历了对应特征空间下的重新拟合，最终保存的是完整可独立加载的模型，而不是在推理时临时删除某些权重。

本次核验发现两版分类器系数均采用 float64。压缩的作用来自维度减少，数值精度保持一致。包含分类器系数、截距和 IDF 的主要数值数组从 480008 字节降到 160008 字节；可学习参数与固定统计量分开列示，有助于解释模型表达能力和资源占用之间的关系。

## 3.5 压缩候选选择与精度控制

原实验先比较词级 1–2 gram 的 20000 特征候选与字符级 3–5 gram 的 30000 特征候选，验证集未经校准的宏平均 F1 分别为 94.06%和 97.69%。据此选择字符级模型作为完整基线。随后对字符模型考察 10000 和 18000 两个容量，按验证集下降不超过 1 个百分点的规则选择可行候选。

10000 特征候选的验证集宏平均 F1 为 97.36%，相对完整模型下降 0.33 个百分点，满足预设容差。候选列表按照较小容量优先检查，选中后保存为部署文件。这个规则将资源目标放在可接受的质量范围内执行，使模型选择过程可以通过代码和记录复查。

```python
candidate = train_text_candidate(train, "char", 10000)
raw, actual = text_raw(candidate, validation)
val_f1 = f1_score(actual, raw >= 0, average="macro")
within_tolerance = val_f1 >= full_val_f1 - 0.01
```

完成模型选择后，原实验在验证集上拟合 sigmoid 校准参数，并在同源测试集上记录部署模型的准确率与宏平均 F1。模型容量选择、概率校准和最终测试具有不同作用：容量选择决定保留哪些表示，校准调整分数尺度，测试给出固定划分上的分类结果。报告在比较表中保持这些指标的原有定义。

## 3.6 图像推理导出与接口保持

图像分支将最佳状态的网络切换为 eval 模式，使用形状为 1×3×32×32 的输入完成 torch.jit.trace，再将图对象保存为 image_detector.ts。评估模式固定批归一化行为，推理上下文停止构建训练所需的自动微分图。导出后以独立加载方式重新读取推理文件，确认文件具备实际执行能力。

```python
model.load_state_dict(checkpoint["state_dict"])
model.eval()
traced = torch.jit.trace(model, torch.rand(1, 3, 32, 32))
torch.jit.save(traced, "image_detector.ts")
with torch.inference_mode():
    logits = traced(batch_tensor)
```

两条图像推理路径使用相同的 RGB 解码、像素缩放和通道排列。图片先转换为 float32，再将像素值缩放到 0 至 1，并从高度宽度通道排列改为通道高度宽度排列，最后增加批维度。后处理阶段由两个 logit 得到分类分数，接口输出保持一致。

TorchScript 是本项目现有交付格式。当前 PyTorch 文档建议新项目采用 torch.export 等后续路径，本报告围绕已有文件完成性能和一致性复核，并在展望中给出迁移顺序。[5] 这样既保持现有部署可用，也能够将后续执行引擎替换建立在同一套输入输出检查之上。

## 3.7 测量设计与计时实现

性能测量固定随机种子为 42，图像输入使用程序生成的 32×32 float32 张量，文本输入使用固定的英文说明段。程序生成输入便于稳定控制形状和长度，主要服务于运行成本测量。标签相关的准确率沿用原实验测试记录，不在运行基准中混入新的类别假设。

每个主对照先执行 25 次预热，再计时三个轮次。单样本每轮记录 200 次，合计每种方法 600 次；批大小为 32 时每轮记录 80 次，合计 240 次。第二轮交换优化前后的执行顺序，减少固定顺序带来的缓存和系统负载偏差。计时采用 perf_counter_ns，结果换算为毫秒后保存完整数组。

## 3.8 内存采样与长时间调用验证

文本内存测量分别启动独立子进程。每个子进程先导入相同的基础库，记录工作集基线，再加载一种模型并读取加载后的工作集。独立进程可避免完整模型和压缩模型共存，使两版对象的生命周期、加载过程和峰值统计保持清晰。

模型加载后先推理 50 次，使必要缓存进入稳定状态，再连续调用 1000 次，每 10 次读取一次进程工作集，共保存 100 个采样点。程序另外保存操作系统记录的进程峰值。稳定阶段波动按照采样最大值与最小值的差除以采样均值计算，与任务书的 5%稳定性目标进行比较。

内存分析采用三个尺度：主要数值数组是模型直接持有的数值数据；加载增量是加载后工作集与基础库基线的差；进程峰值包含解释器和库运行开销。三个尺度共同解释压缩收益。文件较小的模型可以明显减少相关对象的加载成本，而整个进程仍需承担相同的基础运行环境。

## 3.9 推理输出一致性与测试流程

图像导出一致性使用 128 个固定种子随机输入和包内两张教学图片，共 130 个输入进行比较。随机输入分成四个 batch=32 的张量，两张图片分别按原预处理方式读取。每个输入同时通过原生模型和导出模型，记录最大绝对 logit 差以及 argmax 类别差异数量。

一致性检查覆盖了单张和批量两种形状。网络在导出示例中使用单张输入，而本次批处理验证进一步确认当前卷积、池化和线性操作能够接受 batch=32。比较过程中两版网络都处于评估状态、使用同一 CPU 数据类型，并关闭梯度记录，以保持数值路径一致。

模型文件校验、结构读取、运行基准、内存子进程和结果写入由同一脚本顺序执行。任一文件指纹不匹配或推理调用失败，流程都会停止。测量完成后生成 measurements.json，并保存终端日志。业务服务的健康检查和先前已完成的上传导出验证作为部署可用性的配套资料，性能结论主要来自本次独立模型测量。

## 3.10 优化部署思路与后续引擎适配

本地部署保留“一次加载、多次推理”的模型生命周期。模型加载放在服务初始化或首次使用阶段，单次请求只完成输入处理、特征计算、推理和结果整理。文本采用稀疏矩阵与线性分类器，图像采用固定空间尺寸的可执行图，二者分别复用已经加载的对象。

ONNX Runtime 的适配重点是导出算子覆盖、输入动态轴、线程配置及图优化级别。图像模型可先保留 FP32，通过固定样本比较 logit，再测量原生与 ONNX 的延迟；待输入输出一致性稳定后，才进一步比较融合和低精度策略。ONNX Runtime 文档提供基础、扩展和布局等图优化机制，可据模型特征逐步选择。[6]

TensorRT 面向 NVIDIA GPU 及其支持的平台，本机 AMD 显卡环境选择 CPU 作为统一对照条件。[7] OpenVINO 的后续验证可以围绕延迟和吞吐性能提示、并发请求数以及 CPU 线程展开，仍沿用本实验的同输入对照、预热、计时和归档规则。[8] 本次结果表中的引擎实测范围为 PyTorch CPU 与既有 TorchScript 文件。

# 四 实验关键技术与难点

## 4.1 将任务书优化方向落实到实际模型

任务书以 ResNet 和 DistilBERT 举例说明优化方法，而本项目的已训练模型规模更小、结构也更简单。合理的实现首先要识别模型中的主要成本：卷积网络具有规整张量运算，字符模型具有稀疏特征和字符串处理。资源优化因此落在词表、IDF 数组和分类器系数规模上，推理优化则落在执行图组织和批量处理上。

这一适配保留了实验目标中的核心问题，即在质量容差内减少部署成本。参数量、文件体积和内存分别建立对照，计算量依据实际结构统计，速度则由运行测量给出。通过这种方式，优化结果能够直接对应项目文件和代码，课程中的方法也能与真实系统的技术选择相连接。

## 4.2 特征裁剪与数值量化的区别

在本实验文本模型中，完整版本与压缩版本均使用 float64 系数。数值位宽保持一致，减少的是特征维度和对应统计量。量化则在既定表示上采用较低精度的数值编码，需要选择尺度、零点或其他映射参数，并考察由离散化带来的计算与分类变化。两种方法可以组合，但本次报告的资源收益按词表裁剪这一实际操作统计。

词表规模从 30000 减少到 10000，系数向量与 IDF 数组各减少 20000 个元素。按每个 float64 数值 8 字节计算，主要数值数组总共减少 320000 字节。序列化文件还包含词条、字典索引、估计器属性和压缩编码，文件变化因此需要直接读取文件大小，而不是只用数组数量推算。

## 4.3 稀疏表示下的计算量分析

对于一条输入，逻辑回归最终计算稀疏向量与权重的内积。其直接乘加数量主要随非零特征数变化，而非随词表总维度线性变化。本次固定英文段在完整词表下产生 418 个非零特征，在压缩词表下产生 369 个。主要稀疏点积的乘加次数减少约 11.72%，明显小于词表维度的减少比例。

字符分解仍需要扫描输入字符串，构建多个长度的 n-gram，随后完成哈希查询、计数、IDF 缩放与归一化。这些步骤在两版模型中继续存在。由此可以预期，文件存储的显著减少未必伴随同比例的单条延迟改善。本机测量正好提供了这种成本分布的实例，为选择优化方向提供了更具体的依据。

## 4.4 图像参数量与执行效率的关系

图像推理导出保留了原网络的层数、通道宽度和权重，因此参数量与卷积乘加量保持一致。性能收益来自推理执行方式的变化，包括减少解释执行环节的开销以及运行时对图的处理。文件体积还会包含图结构与序列化元数据，导出文件因而可能比单独的权重文件更大。

本实验同时给出文件大小、计算量和延迟，使这一现象能够从三个角度观察。若目标是缩小模型本体，需要继续研究通道裁剪或更紧凑的表示；若目标是改善现有小网络的在线响应，可以先优化执行路径和数据准备。采用不同指标描述不同层面的收益，有助于形成明确的工程决策。

## 4.5 测量噪声与统计口径

小模型的单条调用通常小于 1 毫秒，操作系统调度、CPU 频率、后台负载和缓存状态会影响观测值。报告采用纳秒级计时器、预热和多轮采样，并在部分轮次交换方法顺序。全部原始耗时保存在结果文件中，可以进一步检查极端值和分布形态。

单次调用的 P50 与平均值并不总按相同方向变化。尾部调用会拉高均值，吞吐量又由平均时间计算，因此一个方法的中位延迟近似持平时，其平均吞吐量仍可能出现变化。分析时应同时查看 P50、P95 和平均吞吐量，优先给出稳定的量级与明确的差异方向。

图像端到端测量从内存中的 PNG 字节开始，包括解码、RGB 转换、数组构造、张量转换、模型调用和 softmax。该流程与只接收张量的模型基准具有不同边界。报告将二者分表列示，便于分析图像预处理在短请求中的占比，并为服务响应优化寻找下一步重点。

## 4.6 数据特点与优化误差的关联

实验一的图像全部为 32×32，网络主要学习这个尺度上的纹理、颜色和局部空间组合。卷积通道一旦被裁剪，后续特征组合也会变化，因此未来通道剪枝需要同时记录每层保留率和类别误差。当前导出路径保持原运算结构，适合优先检查数值一致性和批维度行为。

文本长度匹配使两类片段在输入规模上接近，减少了分类器仅依靠长度差异区分类别的机会。词表裁剪将低频或弱贡献特征排除在部署空间之外，可能影响包含罕见词形、专有名词或特殊标点的片段。后续完整测试资料归档时，可按长度、稀有字符比例和类别统计错误，使资源优化进一步关联到具体文本特征。

标签质量同样影响优化判断。补充作文集中的写作指令问题说明，评价材料需要同时核对文本内容和标签含义。实验三的压缩选择保持在主验证集内完成，原测试结果与补充数据审计分别呈现。这样的资料组织使质量分析集中在明确的样本范围内。

# 六 实验总结与展望

## 6.1 实验完成情况

本实验完成了针对项目实际模型的资源优化分析和推理验证。文本分支通过特征词表裁剪，将部署文件从 479938 字节减至 167326 字节，同时将验证集宏平均 F1 的变化控制在原实验预设容差内。图像分支完成原生与导出版本的同机比较，单张推理 P50 下降 18.87%，130 个输入的输出检查保持一致。

内存测量进一步说明了资源优化的层次。压缩文本模型的加载内存增量减少约 59.83%，整个进程峰值下降约 8.52%，连续 1000 次调用的采样工作集保持稳定。模型相关对象的缩减已经体现出来，而进一步降低进程成本需要结合依赖加载和服务部署方式处理。

在方法上，实验建立了“固定模型版本、控制输入与线程、预热后多轮计时、按层次记录资源、保存完整结果”的测量流程。通过这套流程，可以把资源、质量和速度之间的关系落到具体文件和运行数据上，为后续引擎迁移提供可复用的比较基线。

## 6.2 小组分工与协作

本次沿用第四组成员，并结合原有职责调整实验三任务。宋凯歌负责整体实验设计、资料核验与报告整合；刘成洋负责参数、存储和内存统计；李阳负责文本基线核查和质量指标整理；魏佳望负责特征压缩、长度相关测量和文本结果分析；史斌斌负责图像结构、推理导出和输出一致性；李羽负责图像批量基准、计算量图表与测试整理。

协作时围绕统一的模型文件和结果格式开展工作。模型结构与数据范围先行核对，测量结果以机器可读文件保存，图表和结论再从记录中整理。分工安排既承接了实验一的数据与模态方向，也使实验三的资源统计、性能验证和结果解释各有对应任务。

## 6.3 后续优化顺序

后续工作优先补齐原始划分、预测明细及完整环境快照，使当前模型能够在同一测试资料上重复评价。文本方面可按长度和罕见字符比例分析压缩后的误差，再考虑更细粒度的特征筛选；图像方面可在当前层级计算量分析基础上比较中间卷积通道的裁剪敏感性。

推理后端迁移可依次完成 torch.export 或 ONNX 导出、FP32 数值核对、图优化级别比较，再根据实际硬件尝试适合的低精度执行。每一步都保持同一模型输入、计时边界和质量资料，逐步明确收益来自结构变化、数值表示还是执行引擎。

对于本地交互系统，下一步可以围绕按需加载和输入准备优化全流程；对于离线集中任务，可以进一步比较批大小、线程和队列调度。当前实验已经形成文本存储压缩与图像推理效率两条清晰结论，也保留了便于继续分析的模型与测量资料。
