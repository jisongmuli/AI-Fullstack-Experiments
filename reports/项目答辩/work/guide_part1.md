# 读懂项目需要哪些编程基础
## 文件 函数 类与模块
**文件**保存代码或数据。`.py` 是 Python 程序，`.js` 是浏览器脚本，`.json` 常保存配置与结构化结果，`.pt`、`.safetensors` 等保存模型参数。扩展名帮助我们判断文件怎样读取。

**变量**给某个值起名字，例如 `stage = "optimized"` 表示选择优化模型。**函数**把一项操作集中起来：输入文本，执行处理，返回结果。`return` 把结果交回调用它的程序。**类**把相关数据和操作放在一起，例如 `CourseDetectors` 同时保存配置、已加载模型与推理方法。

**模块**通常就是可导入的 Python 文件。`from course_preprocessing import canonical_text` 表示复用另一个模块里的函数。复用让训练和推理采用同一套规则，后续修改时也更容易保持一致。

```python
# 教学示例
def choose_label(score):
    if score >= 0.8:
        return "likely_ai"
    if score <= 0.2:
        return "likely_human"
    return "uncertain"

label = choose_label(0.91)
```

这里的 `score` 是参数，缩进表示代码属于哪个分支。字符串是带引号的文字；数字可以比较大小；列表保存一组值；字典通过键保存字段，例如 `{"risk_score": 0.91}`。

## 按调用关系读代码
从按钮开始找请求地址，再找后端对应路由，继续找模型方法。不要从文件第一行一直读到末尾。遇到陌生函数，先记录它的输入、输出和调用者，再了解内部细节。

异常通过 `try` 和 `except` 转成可读的失败说明。调试时看日志定位具体文件和行号，再用最小输入重现问题；修改后用原来失败的情形验证。

# 浏览器页面如何工作
## HTML CSS 与 JavaScript
HTML 描述页面结构，例如上传框、按钮、标题和结果区域。CSS 控制布局、间距、颜色、移动端适配。JavaScript 负责交互，例如读取输入、发送请求、等待结果并更新页面。当前项目直接使用这些浏览器技术，入口文件是 `web/index.html`。

浏览器把页面中的元素组织成 DOM。`document.getElementById` 根据编号找到元素；事件监听把“用户点击”连接到一个函数。项目中的 `web/app.js` 处理通用图文检测，`web/document.js` 处理文档任务，`web/course.js` 处理课程页和助手。

const response = await fetch('/api/course/text/detect', {

# 请求如何到达 Python 后端
## HTTP API JSON 与状态码
HTTP 是浏览器和服务交换请求与响应的规则。URL 中的 `127.0.0.1` 表示本机，端口 `8006` 标识当前服务入口，`/api/course/text/detect` 指定要调用的功能。API 是其他程序可以使用的接口。

GET 常用于读取信息，POST 常用于提交输入，DELETE 用于删除已有记录。JSON 用键值对表达结果；文件上传则通常使用 multipart 表单。FastAPI 根据路由把请求交给指定函数，并用 Pydantic 检查字段类型和长度。

| 状态码 | 在本项目中的常见含义 |
|---|---|
| 200 | 操作成功 可以读取结果 |
| 400 | 输入内容或对话记录格式需要修正 |
| 404 | 路径不存在 或报告已到期 |
| 413 | 文件 字符数或请求体超过限制 |
| 415 | 文件格式不支持 如旧版 DOC |
| 422 | 字段校验失败 或文件正文无法提取 |
| 503 | 模型未就绪 或处理名额已满 |

## FastAPI Uvicorn 与 ASGI
FastAPI 定义接口、校验和响应；Uvicorn 监听端口，接收网络连接；ASGI 是两者衔接所遵循的应用接口规范。它们组合起来，才把 Python 函数变成浏览器可以访问的服务。

`async` 和 `await` 让等待上传、网络等操作更容易并发处理。模型计算会占用 CPU，项目通过线程池执行耗时操作，让健康检查保持响应。异步主要改善调度，神经网络的计算量仍由模型和硬件决定。对应实现见 `code/server/app.py` 与 `runtime.py`，参考资料见 R1。

# 机器学习如何从数据得到模型
## 样本 标签 特征与参数
一个样本是一条待学习的记录，例如一篇文本或一张图片。标签告诉模型这条记录属于哪一类。本项目课程二分类约定 0 为人工或真实内容，1 为 AI 生成内容。特征是程序能处理的数值表示，参数是模型在训练中学到的数值。

训练时，模型先做预测，再用损失函数比较预测和标签。优化器根据梯度更新参数，重复这个过程。推理时加载已保存参数，对新输入做预测。训练需要标签参与更新；线上推理主要需要输入、配置和权重。

**Epoch** 表示遍历一轮训练数据。**Batch** 表示一次处理的样本组。**学习率**控制每次参数调整的幅度。**过拟合**指模型在训练样本上学得很好，换到新样本后表现明显下降。解决方向包括可靠划分、合理模型复杂度、数据增强和验证集选择。

## 张量是什么
张量是多维数值数组。一张 64×64 RGB 图片有三个颜色通道，转换后通常是 `3×64×64`。加上批次维，单张推理输入是 `1×3×64×64`。文本可先变成长度固定的特征向量，也可先分词变成 token 编号。

NumPy 擅长处理数值数组；PyTorch 提供张量运算、神经网络与自动求梯度；scikit-learn 提供 TF-IDF、逻辑回归、指标计算等工具。Transformers 负责加载和调用多种预训练模型，PEFT 负责 LoRA 这类高效微调。

**CPU 与 GPU** 都能执行模型运算。当前电脑的已验证课程计时采用 CPU、4线程。模型文件大小、运行内存、参数量和单次耗时是不同概念，分析性能时应分别看记录。

# 数据预处理怎样影响检测
## 图像预处理
课程图片先根据 EXIF 信息校正方向，再转成 RGB，以 Lanczos 方法调整到 64×64。像素值除以255，随后按训练集计算的通道均值与标准差进行标准化。这样，训练与推理面对相同的数值范围。

训练时随机水平翻转，提高模型对左右方向变化的适应能力；验证和测试保留固定处理。均值与标准差从训练集得到，避免用测试数据帮助确定预处理参数。

## 文本预处理
NFKC 是 Unicode 的一种规范化方法，可以把部分全角、兼容字符统一成对应形式。连续空格、换行和制表符再统一成一个空格。例如全角 `ＡＢＣ１２３` 经规范化成为 `ABC123`。这能减少排版差异对特征的干扰。

```python
# 项目实际使用的共享函数
import unicodedata

def canonical_text(text):
    return " ".join(
        unicodedata.normalize("NFKC", str(text)).split()
    )
```

这个函数位于 `code/models/course_preprocessing.py`，由数据准备和课程推理共同使用。修复前，两个环节的规则分开维护；修复后，全角和空白变体使用一致的特征，长度要求也按规范化正文判断。

**需要保留的区别** 文档标注仍需保留提取原文和字符位置。用于模型计算的规范化文字，与给用户展示的原文，可以各自保留；直接改动展示原文，会使下划线位置和下载报告难以核对。

# 中文基线如何把文字变成分数
## 字符片段与 TF IDF
课程中文模型使用连续2到4个字符组成的片段。例如“训练数据”可产生“训练”“练数”“数据”“训练数”“练数据”“训练数据”等特征。采用字符片段后，可以直接处理中文连续文字。

TF 描述片段在当前文本中出现的频率；IDF 描述片段在训练语料里是否普遍。到处都出现的片段区分力通常较低，较有区别的片段获得更高权重。项目启用对数词频 `sublinear_tf=True`，避免重复次数过多的片段完全主导结果；再进行默认的向量归一化。[R2]

词表通过训练集拟合。新文章使用同一词表转换，未出现的特征位置为0，因此得到的是稀疏向量。完整方案最多12000项特征，优化方案2000项，`min_df=2` 表示训练集中至少两条文本包含该片段才保留。

## 逻辑回归与校准
逻辑回归为每项特征学习一个权重，把特征值与权重相乘后汇总，再加偏置得到分类间隔。项目使用 `C=4`、最多500次迭代。C 控制正则化强度，较小 C 对参数的约束更强。

分类间隔随后通过验证集拟合的 sigmoid 校准转换成模型分数。TF-IDF 和逻辑回归计算较轻，训练过程清楚，适合用来建立可解释、可压缩的课程基线。

**答辩表达** 课程中文基线先用字符 TF-IDF 提取统计特征，再用逻辑回归分类；增强中文检测则使用 MPU Transformer。两种方案承担不同的实验与应用任务。

# 图像 CNN 如何理解图片
![图3 课程卷积网络的形状变化](cnn)

卷积层用可学习的小窗口在图像上提取特征。浅层可以捕捉局部边缘和纹理，后续层组合更复杂的模式。通道可以理解为同一位置的多种特征响应。模型依靠标签学习哪些响应对当前分类有帮助。

每个卷积块由 Conv2d、BatchNorm2d、ReLU 和 MaxPool2d 构成。批归一化帮助稳定训练；ReLU 引入非线性；最大池化减小空间尺寸。三次池化把64×64逐步变成32×32、16×16和8×8。

全局平均池化把每个特征通道汇总成一个值，线性分类头输出两个类别的 logits。项目使用第二类减第一类的间隔，再做校准。训练方案的通道数是16、32、64；剪枝后为12、24、48。

**展示时要说清尺寸** 课程 CNN 统一使用64×64，便于训练与压缩实验；常规大图检测使用 DEAR 的原生图块策略。上传分辨率和送入某个模型的张量尺寸，是两个不同的处理环节。

# 实际训练与压缩怎样完成
## 图像训练与物理剪枝
CNN 训练15轮，batch size 为24，使用 AdamW，学习率0.001、weight decay 0.001，损失函数为交叉熵。每轮记录训练损失和验证 macro-F1，保存验证表现最好的权重。[S3]

剪枝时按卷积权重绝对值之和选择保留通道，重建较窄的卷积、批归一化和分类头，再恢复训练6轮。参数矩阵的形状实际变小，因此减少了参数和计算。优化模型再导出 TorchScript，导出检查的最大 logit 差为0。

# 增强图像检测如何支持大图
## DEAR 方法和本地接入
DEAR 来自 ICML 2026 的公开工作。作者使用局部修补诊断图分析特征通道与生成区域的关系，筛掉两端较脆弱的通道，再调整分类头，改善压缩和缩放后的识别表现。当前项目接入作者发布的检查点。[R5]

本地实现使用带固定通道门控的 ResNet-50，按严格结构加载权重。短边小于512像素时选择 DEAR-c，其余选择 DEAR-r，随后使用各自验证参数校准。较小图片会显示相应适用范围，短边不足16像素时保持不确定决策。

![图4 大图的原生尺度采样](tiles)

4K 图片解码后保留原始分辨率，推理最多选择9个分布在图上的原生尺度图块，通常每块256×256。各块 logit 按实际面积加权汇总。这样限制了计算和内存开销，同时保留采样位置的局部细节。图示表达采样逻辑，采样块之间可以存在未进入模型的区域。

页面的九宫格敏感度通过逐格模糊、比较分数变化获得；C2PA 功能核验文件里的内容凭证。敏感度、凭证和分类分数分别提供模型响应、来源记录和统计判断三个角度的信息。

:::page mpu
# 增强文本模型如何处理长文章
## MPU 与 Transformer 编码器
MPU 是 Multiscale Positive-Unlabeled Detection，论文发表于 ICLR 2024。其训练思想关注短生成文本与人工文本高度相似的情况，通过多尺度处理和 PU 训练改善不同长度文本的识别。当前项目接入作者发布的中英文 v3 Short 权重。[R6]

中文检查点使用 BERT 分类架构，英文使用 RoBERTa 分类架构。它们先把文字转换成 token 编号，再用 Transformer 编码上下文，分类头输出两个类别的分数。这里调用的是已训练的检测模型，课程 CNN 和 TF-IDF 是另外保存的本组训练成果。

![图5 长文本的滑窗与汇总](windows)

每个窗口最多512 token，前后窗口重叠64 token。token 可能是汉字、单词片段或标点，数量与字符数并不相同。代码用批次执行各窗口，并按新增 token 数给窗口间隔加权，减轻重叠部分的重复计算影响。

中文选择与校准的最终配置来自 `text_calibration_phase1.json`，它会覆盖较早的 `text_policy_2026.json` 中同名字段。判断实际运行模型时，需要看配置合并和调用路径。当前中英文最终均采用 MPU；TASTE 作为评估过的候选保留。

:::page calibration
# 模型分数 阈值与校准
## 从分类间隔到模型分数
神经网络或逻辑回归先得到分类间隔 z。校准再计算 `a×z+b`，并通过 sigmoid 映射到0至1。a 和 b 从验证集拟合，帮助分数适应当前数据范围。它们属于模型运行配置，需要和对应权重一起保存。

{{EQ:sigmoid}}

**教学示例** 分数0.91在页面可显示为91/100，表示模型更倾向于生成类。这个数字用于筛查和排序，解释时同时说清模型版本、样本来源、阈值和输入范围。

## 为什么有两种阈值
评估表采用0.5做二分类统计，便于计算准确率、误报率和漏报率。运行页面采用0.2和0.8作为较高置信判断的分数边界：分数不超过0.2倾向人工，不低于0.8倾向AI，中间区间显示不确定。特定输入范围还可以直接返回未评分。

**未评分**的 `risk_score` 是空值，表示未进入当前可靠评分流程；**不确定**则可能已有分数但落在中间区间。两者需要通过字段和页面文案区分。

## 三类页面数字要分开讲
模型分数描述一个输入或片段的分类响应；高亮覆盖率统计达到高风险阈值的字符范围；可评分覆盖率统计进入评分流程的字符范围。文档高亮按片段与字符位置展示，介绍时使用各自的统计名称。

:::page metrics
# 怎样读懂准确率和误报漏报
## 先认清混淆矩阵
把 AI 生成类看成正类。TP 是生成内容被判为生成；FN 是生成内容被判为人工；FP 是人工内容被判为生成；TN 是人工内容被判为人工。**FP 对应误报，FN 对应漏报。**

| 课程优化中文模型 | 预测人工 | 预测生成 |
|---|---:|---:|
| 实际人工 300条 | TN 296 | FP 4 |
| 实际生成 300条 | FN 5 | TP 295 |

{{EQ:precision}}
{{EQ:recall}}
{{EQ:f1}}

用上表计算，准确率是591除以600，即98.50%；精确率是295除以299，约98.66%；召回率是295除以300，约98.33%。误报率是4除以300，约1.33%；漏报率是5除以300，约1.67%。

F1 综合精确率与召回率。macro-F1 先分别计算两类 F1，再平均，避免只看生成类。AUROC 关注分数排序和不同阈值下的区分能力；它和固定阈值下的准确率回答不同问题。

样本不平衡时应同时看类数量、误报、漏报和 balanced accuracy。测出很高的总体准确率后，仍要回到错误样本分析它们来自什么长度、题材和来源。[R3]

# 文档怎样被提取和标注
## 从文件到可检测正文
TXT 和 Markdown 读取文本编码；DOCX 是包含 XML 的压缩包，程序提取正文、段落和表格等文字；PDF 使用文本层提取，并处理按版面分布的文字块。扫描图片 PDF 需要先具备可读文字层，当前流程主要分析可提取正文。

提取后保留文字及其区段信息。程序对文档中符合范围的段落调用文本检测，再把评分片段对应回原文位置。引用、代码、写作指令和过短文本有相应处理规则，页面同时展示评分覆盖情况。

## 字符位置为何容易出错
Python 字符串索引和浏览器 JavaScript 的字符串索引在某些字符上不同。例如部分 emoji 在 JavaScript 中占两个 UTF-16单元，而 Python 常按一个 Unicode 码点处理。项目用相应转换保持段落下划线与原文位置一致。

换行也会变化：浏览器表单可能发送 CRLF，Python 内部可统一成 LF。标注范围必须对应同一份原文版本。SHA-256 用来帮助核对上传字节或规范化粘贴正文，字段会记录指纹对应的对象。

| 文档输入边界 | 当前设置 |
|---|---:|
| 单个文档文件 | 20 MiB |
| 提取或粘贴正文 | 100000字符 |
| 分段数量 | 2000 |
| PDF页数 | 200页 |

压缩包展开、XML和PDF流还各有资源限制，避免异常文件占用过多内存。提取逻辑、检测统计和导出逻辑分别位于 `documents.py`、`app.py` 与 `document_reports.py`，方便单独验证。

# 长任务和报告怎样管理
## 先拿任务编号 再查看进度
长文档使用后台线程任务处理，前端先拿到 `job_id`，再定期查询进度。任务包含提取、分析、保存等阶段，最终进入完成、失败或取消状态。刷新页面后，前端可以重新读取服务中的任务列表；服务进程仍在运行时，后台计算可以继续。

用户取消任务会设置取消标记。工作线程在阶段边界和处理循环检查标记，再收尾释放处理名额。前端“停止等待”和服务“真正结束任务”需要协同管理，因此取消逻辑属于可靠性设计的一部分。

## 任务和报告各有编号
`job_id` 标识一次处理过程，`report_id` 标识一份已生成报告。文档导出接口按报告编号读取结果，再生成 DOCX、HTML 或 JSON。报告将提取正文、评分、模型版本和时间等内容组合起来。

| 报告缓存设置 | 当前值 | 目的 |
|---|---:|---|
| 最多报告数 | 20份 | 控制条目数量 |
| 总体积上限 | 32 MiB | 控制运行内存 |
| 有效时间 | 1800秒 | 定时清理过期内容 |
| 存储位置 | 服务进程内存 | 本机短期使用 |

页面列表和下载报告都受有效时间约束。重启服务后，内存任务和报告重新开始；正式长期保存需要另行设计数据库或对象存储。

Word 与 HTML 导出在提取文字上添加标注，JSON 保留机器可读详情。导出时按报告内容生成新文档，原上传文件的完整排版可在原文件中查看。
