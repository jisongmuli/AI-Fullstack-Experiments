# 英文编辑与两类大模型怎样区分
## 规则编辑做什么
`editing.py` 按预设规则改善英文表达，例如把不必要的长表达换成简洁形式。程序同时比较数字、否定词、引文、缩略词和词汇重合情况；若候选触发表面检查，保留原文，并列出待人工处理的建议。

**教学示例** 原文含有 `in order to` 时，可以考虑替换为 `to`。如果修改同时改变了实验数量、百分比或否定关系，应先核对原意。规则可以检查已定义的模式，作者最终负责确认事实和表达。

## 可选的英文大模型预览
编辑预览使用本地 SmolLM2-135M-Instruct 和已有英文编辑 LoRA。当前接口接受20至320字符、满足英语范围要求的短段落，生成后再经过候选筛选。页面根据结果展示待核对候选、范围说明或拦截原因。

| 模型或程序 | 当前职责 | 主要位置 |
|---|---|---|
| 规则编辑 | 可控表达替换与建议 | editing.py |
| SmolLM2 加编辑LoRA | 短英文生成式预览 | llm_preview.py |
| Qwen3.5 加路由LoRA | 选择工具及汇总结果 | agent_model.py |
| MPU | 判断中英文生成信号 | research_detectors.py |

Qwen 助手可以调用规则编辑 API。助手里的工具路由适配器与 SmolLM2 的编辑适配器分别保存，微调目标、权重和调用路径各自明确。

**答辩表达** 系统既有可控的规则编辑，也有可选的大模型预览；内容检测、工具选择和生成式编辑由不同组件完成。这样可以分别测试每个模块，并在界面展示处理依据。

# 大语言模型需要掌握的基础
## token 上下文与生成
大语言模型把输入转为 token 编号，根据上下文计算下一个 token 的可能性，再逐步生成文字。**上下文**包括系统要求、用户输入、对话历史等已提供信息。**提示词**就是交给模型的操作要求和上下文内容。

Transformer 中的注意力机制，让模型根据任务计算不同位置之间的相关性。检测用的 BERT、RoBERTa 主要把输入编码成表示后做分类；助手使用因果语言模型，根据已有内容预测后续输出。当前 Qwen3.5 的运行类是 `Qwen3_5ForCausalLM`。[R4]

## 模型大小与运行资源
0.8B 是模型系列的参数规模标识，B 表示十亿量级。实际内存还包含输入、缓存、中间激活和框架开销。项目保存完整官方检查点，运行助手时载入文本骨干；图像由图像检测工具处理。

本地助手采用 BF16 运算。BF16 是一种16位浮点表示，可以降低部分权重和计算的存储开销；它与“把模型量化为4位”是不同技术。选择当前模型主要考虑本机 CPU 和内存条件，以及课程展示所需的任务规模。

## 温度与确定性
生成时的随机采样会影响答复。当前助手汇总使用 `do_sample=False`，最多生成72个新 token，并设置生成时间边界。工具路由则直接比较允许计划对应字母的下一个 token 分数。

大模型的自然语言答复可能遗漏细节，因此界面保留实际 API 结果。答辩时先展示工具路径和 HTTP 状态，再阅读汇总答复，就能把模型解释与程序实际执行对应起来。

# Agent 如何选择允许的工具
## 从操作要求到计划字母
助手先接收用户操作说明，并知道当前是否有正文、图片和文档。LoRA 模型在允许的计划字母中选一个；服务端把字母对应到工具列表。每次最多执行两个工具，所需输入也会先检查。

| 计划 | 对应工具 |
|---|---|
| A | 查看模型信息 |
| B | 查看课程实验 |
| C | 检测正文 |
| D | 检测图片 |
| E | 检测文档 |
| F | 英文清晰度编辑 |
| G | 图片检测和正文检测 |
| H | 图片检测和文档检测 |
| I | 正文检测和英文编辑 |
| J | 请求补充输入 |

如果没有图片，依赖图片的计划不进入候选；如果只有文本，模型就在与现有输入相容的计划中选择。这是服务端约束与语言模型配合的设计。

页面保留最多六条历史消息供请求使用，规划时使用其中最近两条的简短上下文。当前系统通过固定工具计划完成受约束的任务组合，工具执行过程有明确记录。

**需要掌握的术语** Agent 是能够根据目标组织工具调用的助手；工具是后端提供的具体功能；路由是从需求选择工具；编排是按计划执行并收集结果。本项目把这几步分别放在模型层和服务层中实现。

# 稳定性设计与已修复的问题
## 限制资源并保持可恢复
全局检测处理名额默认为2，助手编排名额为1。占满时返回503和稍后重试提示。图片文件限制为25 MiB、解码后最多2500万像素，API请求体上限为35 MiB。运行状态接口只返回汇总计数，便于页面显示“服务就绪”或“处理中”。模型按需加载，读取模型信息时采用轻量文件检查。

| 问题情形 | 当前处理 |
|---|---|
| 损坏图片或文档 | 提前校验 返回可读说明 |
| 请求体或文件过大 | 超限拒绝 控制内存 |
| 异常对话角色或工具计划 | 类型及允许范围检查 |
| 单个工具返回异常 | 保留失败记录 继续其他工具 |
| 新输入碰到旧响应 | 版本和状态检查 取消迟到请求 |
| 文档任务取消或失败 | 收尾释放名额 清理临时结果 |
| 报告过期或被删除 | 返回状态说明 引导重新检测 |

## 三种测试分别检查什么
单元测试针对输入校验、状态转换、计算和错误处理。集成测试把服务、文件解析、模型和导出连接起来。浏览器测试模拟点击、上传、页面切换、下载和移动布局。测试里的受控故障用于稳定复现异常，真实模型请求则验证实际调用链。

一个例子是旧版 DOC 上传：以前提取异常会造成500，现在返回415和转存 DOCX 的说明，随后可以重新提交。另一个例子是课程样例下载：失败时保留五张实验卡片，离开页面取消等待，返回迟了也不会覆盖新输入。

**答辩表达** 我们把正常检测和失败恢复一起验证；一次失败后还能继续操作，是系统稳定性的重要表现。

# 项目整体介绍参考讲稿
各位老师好，我们展示的项目是内容可信工作台。系统支持图像和中英文文本筛查、文档分析、英文编辑，也提供课程实验总览和大模型助手。

项目按五次实验逐步完成。首先建立数据来源和处理规则，保存文件指纹、标签与训练验证测试划分。当前课程使用400张2026年图片和4000条中文文本，文本按原始组划分，避免成对内容跨集合。

第二步实际训练课程CNN和中文TF-IDF分类器。第三步进行算法优化，CNN按通道重要性剪枝并恢复训练，文本通过验证集选择较小词表。优化记录同时保存质量、体积和计算时间，让我们看到每种取舍。

第四步用FastAPI把模型提供为API，浏览器可以直接上传图文和文档。课程训练基线、课程优化模型都能实际调用；日常筛查使用接入的DEAR和MPU增强检测器。文档功能保留提取正文和片段位置，支持进度、取消、报告管理与多种导出。

第五步部署本地Qwen3.5，并进行LoRA工具路由微调。模型从允许的计划中选择工具，服务调用真实检测API，再根据结果生成简短答复。界面保留路径、状态和原始返回，方便核对。

工程上，我们加入输入上限、并发控制、按需加载、报告到期清理和失败恢复。最近一次记录中178项测试通过，20项浏览器检查通过，680条保留样本的实际API输出与保存预测一致。

这个项目的特点是把课程实验做成可复查的应用：从哪份数据得到哪份权重、怎样压缩、由哪个接口执行、输出如何解释，都能找到相应记录。接下来我们按实际页面演示这条流程。

# 模型与实验常见追问
## 你们自己训练了哪些模型
课程CNN、课程中文TF-IDF分类器及Qwen工具路由LoRA有实际训练与结果记录。DEAR、MPU和Qwen基础权重来自公开上游，项目负责接入、策略、校准、评估与应用集成。

## 既然有大模型 为什么还用TF IDF
它训练和运行较轻，词表、权重和压缩过程容易复查，适合建立课程基线。增强检测使用另一套预训练模型，可以根据场景选择。

## 为什么CNN压缩后准确率下降
减少通道降低了容量，恢复训练后仍有质量取舍。记录中参数和耗时下降，80张测试图准确率降低2.5个百分点。介绍优化时把质量与资源一起看。

## 为什么训练 验证 测试要分开
训练学习参数，验证选择方案，测试统计选择完成后的表现。若根据测试成绩反复挑模型，就把测试信息带回了模型选择过程。

## 如何知道数据没有泄漏
检查文本组ID和内容指纹跨集合无交集，图片检查像素指纹并排除已有审计ID。课程完整清单和划分测试都保留在仓库中。

## 什么情况下有分数但仍显示不确定
页面的置信边界为0.2与0.8，中间区间显示不确定；评估准确率采用0.5。较小图片等特定输入还会有额外范围处理。

## 哪个数字最能说明准确率
先说明具体任务、模型、样本量、来源和阈值，再给准确率、误报和漏报。类别不平衡时增加balanced accuracy、F1和AUROC，最后查看错误样本。

# 工程与系统常见追问
## 前后端是怎样通信的
浏览器用fetch发送HTTP请求，JSON传正文和配置，FormData传文件。FastAPI校验输入、调用服务，再返回JSON或下载文件。

## 为什么选择本机运行
本机部署适合课程现场演示，数据和模型就在当前电脑，运行条件容易控制。进一步面向多人使用时，再补充身份、持久存储、部署监控和容量设计。

## 当前数据保存在数据库吗
报告和任务短期保存在服务内存，报告数量、体积和有效时间受限制。训练数据、权重、配置与实验记录是项目目录中的文件。

## 4K图片是怎样处理的
常规DEAR路径保留解码原图，最多取9个原生尺度图块并汇总分数。课程CNN路径会统一到64×64，展示训练与压缩过程。

## Agent真的调用了功能吗
查看工具记录里的接口路径、HTTP状态、耗时和返回结果。它通过ASGI请求同一应用API；图片和文档都由对应服务完成具体分析。

## 长文档为什么适合后台任务
后台处理允许页面查看进度和恢复等待。任务结束、失败或取消时会收尾释放名额。任务状态和最终报告通过不同编号查询。

## 目前最值得继续改进什么
围绕真实目标场景扩充来源、长度和生成器覆盖，分析误报漏报；继续提高课程CNN质量，并在新来源上校准和评估。工程上可按多人使用需求增加长期存储与部署监控。

**回答追问的方法** 先给当前实现，再指出对应文件或记录，最后解释原因。拿不准的数字直接打开结果文件核对，保持模型、数据切片与阈值一致。
